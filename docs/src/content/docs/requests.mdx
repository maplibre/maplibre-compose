Tiles, sprites, and fonts come from URLs in the style. Rewrite those requests,
or serve the bytes from application code.

<Api of="MapRequestInterceptor" /> rewrites a resource URL or adds HTTP
headers before the engine fetches it. It can rewrite a custom-scheme URL to
HTTP or HTTPS, and the headers apply to the rewritten URL.
<Api of="MapResourceProvider" /> supplies resource data without the engine HTTP
client and receives the rewritten URL. Both hooks are fixed when the runtime
is created and apply to its maps, snapshotters, and supported offline operations.

Attach credentials only to hosts you own. A style also names glyphs, sprites,
and tiles on other hosts. The provider's scheme factory accepts every URL with
that scheme.

The application owns the token state. Updating its value lets subsequent header
callbacks read refreshed credentials without replacing the interceptor or
recreating the runtime. Callbacks must return quickly and be safe to call
concurrently. The engine may call them more than once for one request; return
the same result while the request and application state are unchanged. Updates
do not restart requests in flight, and separate callbacks may observe different
credential values.

For screen-specific configuration, use <Api of="createMapRuntime" /> with its own
options and pass the runtime to <Api of="rememberMapState" />. Keep that runtime
for the lifetime of its owner, which must call <Api of="MapRuntime.close" /> when
finished. Use <Api of="MapRuntime.awaitClosed" /> when cleanup must finish before
proceeding. Configure the process default at startup rather than from a screen's
composition.

## Serve the bytes

A load returns a <Api of="MapResourceLoad" />. Each case corresponds to one
HTTP response. Return `Bytes` with the body. Return `NoContent` for a tile
outside the data set, and the map renders an empty tile without an error.
