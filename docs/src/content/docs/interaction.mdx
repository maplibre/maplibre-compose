## Choose scroll behavior

A `mappings` block replaces a family's camera responses. The first matching row
with a permitted response wins. Here Ctrl-scroll zooms, continuous scrolling
pans, and other scrolling zooms:

<Code code={region(interaction, "scroll-mappings")} lang="kotlin" title="App.kt" />

The rows are configuration, built before input arrives. You can use ordinary
Kotlin `if` statements to include rows for an app mode. `none()` ends matching
without a camera response. An empty table removes camera responses but preserves
eligible app click delivery; `enabled = false` disables that input family.

Drag, tap families, and keys have the same table structure with responses suited
to their input. Single-pointer drag and two-finger transform pan are independent.
Tab focuses the map; Enter engages keyboard navigation, and Escape leaves it.

## Stop following when the user pans

A camera component's `onStart` runs before its first effective response. Pan
observation covers drag, two-finger pan, scroll, keys, and external camera input,
without treating anchored zoom or rotation as panning:

<Code code={region(interaction, "pan-observer")} lang="kotlin" title="App.kt" />

For editing features, `bindings.drag.custom("edit-handle")` accepts a synchronous
`canStart` hit test and one `onEvent` lifecycle callback. The key identifies the
same app drag across recompositions. Update a preview on Delta, commit on End,
and discard it on Cancel. A declined hit test leaves ordinary navigation
available. Selection and edit state belong to the app.

Callback body changes do not restart input. Changing mappings, thresholds, or
camera permissions cancels active input. Compose consumption also cancels
input already claimed by another composable.

## Handle clicks

The `callbacks` block provides `click`, `doubleClick`, `contextClick`, and
`twoFingerClick`. Events include geographic positions when projection is
available and map-local screen offsets in dp. A context click can come from a
long press or a secondary mouse click; their recognition settings are independent.
Return <Api of="ClickResult.Pass" /> to continue to interactive layers, or
<Api of="ClickResult.Consume" /> to stop delivery and suppress the camera fallback.

To query features yourself, consume synchronously and launch the query in your
own coroutine. Its eventual result cannot change the returned click decision:

<Code code={region(interaction, "click-listeners")} lang="kotlin" title="App.kt" />

Layer handlers receive matching features. `onContextClick` handles context
requests. `hitPadding` makes small targets easier to select: zero queries an
exact point, while positive padding queries a square around it. It applies to
all four click kinds.

<Code code={rememberedMapStyle(region(layers, "interaction"))} lang="kotlin" title="App.kt" />

Delivery runs through the map callback and interactive layers in loaded
front-to-back order. An ordinary click can then reach `click.onUnhandled`.
After Pass, a tap's selected camera response runs if it is still valid. Feature
dispatch does not reverse Compose pointer consumption or forward a click to a
parent composable.

`callbacks.hover.onEvent` reports pointer entry, movement, and exit without
feature queries. Layer `onHover` handlers additionally receive exact-point hits.
Hover updates beneath a stationary pointer when the camera or style changes,
does not consume input, and does not use click hit padding.

This scope respects the attached map's camera permissions, including when using

or an ordinary camera mutation can take over and cancel it. Do not retain the
scope after its block returns or nest input scopes for the same map.

## Platform input

Gesture bindings use the events delivered by the Compose host. Trackpad support
therefore differs by host:

| Host            | Trackpad route                                                                      |
| --------------- | ----------------------------------------------------------------------------------- |
| Android 34+     | Classified Scale/Pan events; touchscreen pairs use touch recognition.               |
| iOS             | Indirect scrolling; dedicated indirect pinch is not provided by the current bridge. |
| AWT desktop     | Scrolling; no native pinch or rotation bridge.                                      |
| Nucleus macOS   | Magnify, rotate, and smart magnify become synthetic touch pairs.                    |
| Nucleus Wayland | Pinch and rotation become synthetic touch pairs; X11 has no equivalent route.       |
| Nucleus Windows | Ctrl-wheel pinch becomes a synthetic touch pair; no rotation route.                 |
| Browser         | Ctrl-wheel zoom and classified wheel scrolling.                                     |

Nucleus places synthetic contacts on either side of the cursor. Near a map edge
or inside a narrow map, both contacts may not reach the same map. Those contacts
report Touch, so a pointer-type setting cannot distinguish them from a
touchscreen. The current Nucleus macOS/Linux bridge also reports release before
native cancellation; the map cannot recover a Cancel event from that release.
Ordinary Compose cancellation remains supported.

Scroll and platform Scale/Pan streams add no library momentum. Their remaining
movement comes from the operating system. Touch pairs, including Nucleus
synthetic pairs, use their configured momentum settings.
