Users can pan, zoom, rotate, and pitch the map by default.
<Api of="MapInteractions" /> sets which of these camera movements users can
make and what your app does when they click. <Api of="MapUiOptions" /> sets
which gesture, scroll, or key does what.

## Restrict camera movement

Turn off a camera movement when your map must stay a certain way, such as
north-up and flat. This map can be panned and zoomed, but not rotated or
pitched:

<Code code={region(interaction, "camera-movement")} lang="kotlin" title="App.kt" />

Settings that you leave out keep their defaults. To turn off every camera
movement, pass `MapInteractions.None`; clicks still reach the layers'
`onClick` handlers. To make the map ignore all input, including clicks, pass
`MapUiOptions.None` as `uiOptions`. To keep the camera inside an area or a zoom
range instead, see
[Limit where the camera can go](/maplibre-compose/camera/#limit-where-the-camera-can-go).

each time the user starts to pan:

<Code code={region(interaction, "pan-start")} lang="kotlin" title="App.kt" />

## Respond to map clicks

Use `callbacks.click` to get the geographic position that the user clicked, for
example to drop a pin there:

<Code code={region(interaction, "map-click")} lang="kotlin" title="App.kt" />

The callback runs before any layer receives the click. Return
<Api of="ClickResult.Consume" /> to stop there, or
<Api of="ClickResult.Pass" /> to let layers receive the click too. For a touch
long press or a right click, use `longClick` in the same way.

## Respond to clicks on a layer

Give a layer an `onClick` handler to let users select its features. This map
reports the earthquake that the user taps, and reports `null` when they tap
anywhere else:

<Code code={region(interaction, "layer-click")} lang="kotlin" title="App.kt" />

`onClick` receives the layer's features at the click, topmost first. Its
receiver is the <Api of="ClickEvent" />, so the handler can also read
`position` and `screenOffset`. `hitPadding` widens the area around the click
that counts as a hit, which makes small circles and thin lines easier to tap.

When several layers have features at the click, they receive it from the top
layer down until one handler returns `ClickResult.Consume`. If none does,
<Api of="ClickCallbackBuilder.onUnhandled" display="onUnhandled" /> runs. To
change how the selected feature looks, see
[Query and highlight features](/maplibre-compose/features/).

## Change what scrolling does

Scrolling zooms the map by default. This map pans when the user scrolls and
zooms when they hold Ctrl and scroll:

<Code code={region(interaction, "scroll-mappings")} lang="kotlin" title="App.kt" />

A `mappings` block replaces the default mappings. The map uses the first `on`
row that matches the input, and `otherwise` matches any other input. Drags, taps, and keys
have their own `mappings` blocks in `bindings`.

## Change haptic feedback for rotation

On Android, iOS, and macOS, the device gives haptic feedback when the user
rotates the map past north. Use `haptics` to choose the bearings and how strong
the feedback is. This map gives subtle feedback every 15°, standard feedback at
east, south, and west, and emphasized feedback at north:

<Code code={region(interaction, "bearing-haptics")} lang="kotlin" title="App.kt" />

A `haptics` block replaces the default north notch. Where notches overlap, the
strongest emphasis wins.

## Pass gestures from your own code

If your app recognizes gestures itself, for example in a host that is not
Compose UI, pass them to the map with <Api of="MapState.panBy" />,
<Api of="MapState.scaleBy" />, <Api of="MapState.fling" />, and
<Api of="MapState.click" />. They follow the same `MapInteractions` settings
and click callbacks as the built-in gestures. See
[Present outside Compose UI](/maplibre-compose/presentation/) for hosts.
