<Api of="MaplibreMap" /> provides the map's Compose UI integration. When another
framework owns the UI, such as Android Auto, CarPlay, UIKit, or SwiftUI, use a
platform presentation to reuse the same map state, camera operations, and
declarative styles.

Create a <Api of="MapState" /> with <Api of="MapRuntime.createMapState" /> and
pass it to a presentation. Your application supplies the host, manages its
lifecycle, and forwards recognized gestures through the
[map's input methods](/maplibre-compose/interaction/#pass-gestures-from-your-own-code).
Compose UI dependencies are still required, but a Compose UI hierarchy is not.

## iOS

<Api of="AppleMapPresentation" /> presents the map, and
<Api of="MaplibreMapView" /> supplies a UIKit view that manages the Metal layer
and its layout:

<Code code={region(apple, "apple-view")} lang="kotlin" title="UIKitMapHost.kt" />

Add the view to a UIKit or CarPlay view hierarchy, or return it from SwiftUI's
`UIViewRepresentable.makeUIView`. Forward activation from the scene hosting
the map; CarPlay has a separate scene from the phone's UI. See
<Api of="MaplibreMapView" /> and <Api of="AppleMapPresentation" /> for ownership,
configuration, and lifecycle contracts.

For hosts that already manage a Metal layer, use
<Api of="AppleMapPresentation.attachLayer" /> directly. This is the same
attachment API used by `MaplibreMapView`.
