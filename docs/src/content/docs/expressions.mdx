A layer property, such as the color of a circle, can have one value for the
whole layer or a different value for each feature. It can also change with the
zoom level. MapLibre describes these properties with expressions: small
formulas inside the style that the map evaluates while it draws. The
[MapLibre Style Specification][spec-expressions] writes expressions as JSON
arrays. MapLibre Compose builds them with typed Kotlin functions from
<Api of="org.maplibre.compose.expressions.dsl" />, so a layer parameter has a
type such as `Expression<ColorValue>`.

## Read feature data

Each feature in a source has properties, such as the magnitude of an
earthquake. The <Api of="feature" /> object reads the data of the feature that
the map is drawing: `feature["mag"]` is its `mag` property. The map learns the
type of a property only when it evaluates the expression, so give the property
a type with a type assertion such as <Api of="asNumber" /> before you compare or
calculate with it. An equality test such as <Api of="eq" /> works without a
type.

<Api of="step" /> picks an output by ranges of its input. <Api of="switch" />
picks the output of the first condition that is true.

## Filter features

## Missing data

A feature does not always have every property. In this data, most earthquakes
have no `felt` value, so `feature["felt"]` is null for them. A type assertion
such as `asNumber()` fails on null. When an expression fails for a feature,
MapLibre uses the default value of the property for that feature, and a filter
that fails hides the feature.

To choose the value yourself, give the type assertion a fallback. To skip
features that lack the value, filter them out.

<Code code={rememberedMapStyle(region(expressions, "missing-data"))} lang="kotlin" title="App.kt" />

To use the first of several properties that has a value, use
<Api of="coalesce" />. The <Api of="Expression" /> reference lists which
functions accept a missing value.

The Kotlin `if` reads app state and picks one stroke color for the whole layer.
When the system theme changes, the content recomposes and the layer gets the
new color. The `switch` expression reads the data of each earthquake, which
Kotlin code cannot see, and picks a fill color for each one.

Use Kotlin for choices that depend on app state, and expressions for choices
that depend on feature data or zoom. To change how one feature looks when the
user selects it, use feature state; see
[Query and highlight features](/maplibre-compose/features/).
