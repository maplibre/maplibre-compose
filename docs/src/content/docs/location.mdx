The dot requires location access.
[Request location permission](#request-location-permission)
when the user chooses to display their location.

The example uses these APIs:

- A <Api of="LocationProvider" /> reads the device's location.
  <Api of="rememberDefaultLocationProvider" /> returns the provider for the
  current platform.
- <Api of="rememberLocationState" /> collects location updates from the provider
  while the screen is visible and stores the latest one in
  <Api of="LocationState.lastLocation" />.
- <Api of="org.maplibre.compose.layers.LocationIndicatorLayer" /> draws a dot at
  that location, with a circle that shows its accuracy. It draws nothing until
  the provider reports a location.
- <Api of="LocationTrackingEffect" /> runs its block each time the location or
  its direction changes. The example sets the zoom for the first location,
  then uses <Api of="updateCamera" /> to center the camera on each update.
  By default, `updateCamera` also rotates the map to the user's movement
  direction or the device's heading, when available. Pass
  `updateBearing = BearingUpdate.Ignore` to preserve the camera's bearing.

An optional heading provider supplies the device's compass direction, which
the dot displays when available.
<Api of="rememberDefaultHeadingProvider" /> reads the compass on Android and
iOS, and supplies no heading on other platforms.

Pass `enabled = false` to `LocationTrackingEffect` to stop moving the camera.
Use [camera gesture events](/maplibre-compose/interaction/#detect-when-the-user-moves-the-camera)
to disable tracking when the user pans the map.

## Configure location updates

By default, `rememberLocationState` requests high accuracy and at most one
location update per second. To reduce battery use, configure lower accuracy or
less frequent updates with <Api of="LocationRequest" />.

## Request location permission

The library does not request location permission automatically. Call
<Api of="LocationState.requestPermission" /> in response to a user action,
such as pressing a button to display their location:

<Code code={region(location, "permission")} lang="kotlin" title="App.kt" />

The platform shows its permission dialog.

If the user denies access, use the properties of
<Api of="LocationPermission.NotGranted" /> to determine whether to request
permission again or open system settings:

- `shouldShowRationale` is `true`: explain why your app needs the location, then
  request permission again. Only Android sets this property.
- `canRequest` is `true` or `null`: you can request permission again.
- `canRequest` is `false`: only the system settings can change the permission.
  <Api of="rememberSystemSettingsLauncher" /> opens them on the platforms that
  support this action.

## Handle location errors

Use <Api of="LocationState.availability" /> to check for missing or
misconfigured location support. <Api of="LocationState.status" /> reports interruptions to
location updates, such as disabled location services. Display a message and
call <Api of="LocationState.retry" /> when the user chooses to retry:

<Code code={region(location, "status")} lang="kotlin" title="App.kt" />

When `availability` is <Api of="LocationBackendAvailability.Misconfigured" />,
its `cause` describes the configuration error.

## Platform requirements

The JVM desktop runtimes in [Platform setup](/maplibre-compose/platform-setup/)
include location support for their operating system.

### Android

Declare the location permissions in your app's manifest:

```xml title="AndroidManifest.xml"
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
```

The default providers use Android's built-in location service. To use Google's
fused location and heading instead, add the optional Google Play services
runtime:

```kotlin title="build.gradle.kts"
androidMain.dependencies {
  implementation("org.maplibre.compose:location-runtime-gms:{{release}}")
}
```

On devices without Google Play services, the default providers still use the
built-in service.

For Huawei devices, `location-runtime-hms` provides fused location through
Huawei Mobile Services. It needs Huawei's Maven repository,
`https://developer.huawei.com/repo/`, and the
[HMS Core setup](https://developer.huawei.com/consumer/en/codelab/HMSPreparation/index.html).

### iOS

Add a location usage description to your app's `Info.plist`. iOS shows this text
in the permission dialog:

```xml title="Info.plist"
<key>NSLocationWhenInUseUsageDescription</key>
<string>Shows your position on the map.</string>
```

### Web

Browsers provide location only on pages served over HTTPS or from `localhost`.
See [secure contexts](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts).

### macOS

For both JVM and native macOS apps, add a location usage description to the
app bundle's `Info.plist`:

```xml title="Info.plist"
<key>NSLocationUsageDescription</key>
<string>Shows your position on the map.</string>
```

Apps using App Sandbox or Hardened Runtime also need the
[location entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.personal-information.location).

For JVM apps packaged with Compose Desktop, set the usage description in
`nativeDistributions { macOS { infoPlist { extraKeysRawXml = ... } } }`.
Configure `entitlementsFile` and `runtimeEntitlementsFile` if the location
entitlement is required.

### Linux

Location uses the
[XDG Location portal](https://flatpak.github.io/xdg-desktop-portal/docs/doc-org.freedesktop.portal.Location.html).
Without the portal, `availability` is `Unsupported`.
