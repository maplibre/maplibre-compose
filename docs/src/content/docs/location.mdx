The location module tracks the user's position and draws it on the map. A
<Api of="LocationProvider" /> supplies location updates,
<Api of="rememberLocationState" /> collects them, <Api of="LocationPuck" />
draws the latest fix, and <Api of="LocationTrackingEffect" /> keeps the camera
in sync with location changes:

<Code code={region(location, "puck")} lang="kotlin" />

All platforms provide default location providers. Android and iOS also provide
default orientation providers. <Api of="LocationState.status" /> reports an
unsupported or misconfigured platform without throwing.

`locationState.location` is null until the first fix arrives, so the puck
initially draws nothing. Afterward, the state retains the last fix when
tracking stops or permission changes.

## Request permission

The library never requests location permission automatically. Call
<Api of="LocationState.requestPermission" /> when the application is ready to
present the platform permission UI:

```kotlin
if (locationState.permission !is LocationPermission.Granted) {
  Button(onClick = locationState::requestPermission) {
    Text("Use my location")
  }
}
```

When permission is not granted, <Api of="LocationPermission.NotGranted" />
reports the next step: explain first when `shouldShowRationale` is set
(Android only), request when `canRequest` is not `false`, and send the user to
the system settings otherwise. <Api of="rememberSystemSettingsLauncher" />
opens the settings screens on the platforms that have them.

```kotlin
val settings = rememberSystemSettingsLauncher()
val permission = locationState.permission
if (permission is LocationPermission.NotGranted) {
  when {
    permission.shouldShowRationale ->
      LocationRationale(onAccept = locationState::requestPermission)
    permission.canRequest != false ->
      Button(onClick = locationState::requestPermission) { Text("Use my location") }
    settings.canOpenApplicationSettings ->
      Button(onClick = { settings.openApplicationSettings() }) { Text("Open settings") }
  }
}
```

## Platform requirements

### Android

Declare `ACCESS_COARSE_LOCATION` and `ACCESS_FINE_LOCATION` in the application
manifest. Declare `ACCESS_BACKGROUND_LOCATION` only when the application tracks
location in the background.

For fused location on devices with Google Play services, add the optional
runtime module. The default providers then use fused location and orientation
where Google Play services is available, and the framework providers
otherwise.

```kotlin title="build.gradle.kts"
androidMain.dependencies {
  implementation("org.maplibre.compose:location-runtime-gms:{{release}}")
}
```

For Huawei devices, `location-runtime-hms` provides fused location through HMS
Core instead. It requires Huawei's repository and
[HMS Core preparation](https://developer.huawei.com/consumer/en/codelab/HMSPreparation/index.html).

### iOS

Add the
[location usage description](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services)
that Apple requires to your `Info.plist`.

### Web

Browsers supply location only in a
[secure context](https://developer.mozilla.org/en-US/docs/Web/Security/Secure_Contexts),
except for development origins such as `localhost`.

### Desktop

On macOS, add the
[location usage description](https://developer.apple.com/documentation/corelocation/requesting-authorization-to-use-location-services)
and the
[location entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.security.personal-information.location)
that Apple requires. On Linux, location comes from the desktop portal on the
D-Bus session bus, commonly backed by
[GeoClue](https://gitlab.freedesktop.org/geoclue/geoclue). On Windows, location
comes from Windows Runtime geolocation. A missing backend reports an
unsupported status through `LocationState.status`.
