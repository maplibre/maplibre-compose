<Api of="AndroidMapPresentation" /> presents a <Api of="MapState" /> on an
Android `Surface` without a Compose UI view. The same state can move between a
Surface and <Api of="MaplibreMap" />. The
[Android Auto demo](https://github.com/maplibre/maplibre-compose/tree/main/demo-app/android-auto)
uses it in a car app.

## Present the state

Create the state with <Api of="MapRuntime.createMapState" />. Its base style,
style content, camera operations, and click handlers work as they do with
`MaplibreMap`. One presentation presents a state at a time. Close it before
presenting the state elsewhere.

Construct the presentation on the main thread with a `Lifecycle`. Rendering
pauses while the lifecycle is stopped. Destroying the lifecycle closes the
presentation. Closing the state also closes it.

`attachSurface` takes the Surface's size in physical pixels and its density in
physical pixels per logical pixel. Keep the returned
<Api of="AndroidMapPresentation.SurfaceBinding" /> and pass size or density changes to
`update`. A density change recreates the native map.

Close the binding before releasing the Surface. Closing waits for rendering to
stop using the Surface. Attaching another Surface closes the previous binding.
A closed binding ignores later updates.

The map produces no frames until its style can be presented. Show your own
loading content on the Surface until then. A map without a style renders black.

Pass a `Configuration` to `updateConfiguration` when the locale, layout
direction, font scale, or night mode changes. Style content reads it through
`LocalConfiguration` and `LocalContext`, and reads the Surface density through
`LocalDensity`. UI composables and view-dependent locals are not available in
style content.

`failure` reports an error that ended the presentation. Create a new
presentation to retry.

## Pass gestures

The presentation has no gesture recognizer. Pass gestures your code recognized
to <Api of="MapState.panBy" />, <Api of="MapState.fling" />,
<Api of="MapState.scaleBy" />, and <Api of="MapState.click" />. They follow the
camera permissions and callbacks in the presentation's `interactions`, interrupt
camera animations, and dispatch clicks to interactive layers. Convert physical
pixels to logical pixels first.
