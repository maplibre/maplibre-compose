The `maplibre-compose-editing` module lets users draw and edit GeoJSON
features on the map. It has three parts: <Api of="FeatureEditorState" /> holds
the features, the active tool, the selection, the draft and the undo history;
<Api of="featureEditor" display="Modifier.featureEditor" /> routes pointer and
key input on the map surface to the tool; and <Api of="FeatureEditorLayers" />
draws the features, the draft and the handles as map layers. Add the
dependency:

```toml title="libs.versions.toml"
[libraries]
maplibre-composeEditing = { module = "org.maplibre.compose:maplibre-compose-editing", version = "{{release}}" }
```

```kotlin title="build.gradle.kts"
commonMain.dependencies {
  implementation(libs.maplibre.composeEditing)
}
```

## Add an editor to a map

This screen lets a user outline one area. The state is remembered across
recomposition and configuration changes, the layers sit under the base map's
labels, and the map's `surfaceModifier` carries the input modifier:

<Code code={region(editing, "basic")} lang="kotlin" title="App.kt" />

1. <Api of="SelectTool" /> is the initial tool. `moveSelected = { false }` keeps
   one-finger drags inside the area as map pans, and
   `clearSelectionOnEmptyTap = false` keeps the area selected so its vertex
   handles stay visible.
2. Layers under labels. See
   [How the map composes](/maplibre-compose/composition/) for anchors.
3. The modifier goes in `surfaceModifier`, not `modifier`, so it sees pointer
   events before the map's gestures and only where no overlay control is under
   the pointer.

<Api of="DrawTool" /> places a vertex per tap. Enter, a double tap, or a tap on
the first vertex finishes a polygon; Escape discards the draft.
`replaceExisting = true` removes the previous area in the same undo step as the
new one. When a draw finishes, the tool set as `nextTool` becomes active with the
new feature selected. `SelectTool` selects on tap, drags vertices and
midpoints, nudges the active vertex with arrow keys, and deletes with Delete or
Backspace. Ctrl+Z and Ctrl+Shift+Z undo and redo while the map has focus.

Taps the tool does not consume, such as a tap on empty map, reach the map's
click callbacks and layer click handlers as usual. Pinch, scroll and camera key
bindings are unchanged.

Features are spatial-k values. Read them from `editor.features`, or export them
with <Api of="FeatureEditorState.toFeatureCollection" />. A `snapshotFlow`
observes every change, including undo, redo and `load`:

<Code code={region(editing, "viewmodel")} lang="kotlin" title="GeofenceViewModel.kt" />

1. The ViewModel creates the state fresh, so it also recreates the `DrawTool`
   that the saved draft belongs to.
2. `cursor` is the mouse position after the placed vertices. Dropping it keeps
   mouse moves from resetting the debounce.

<Api of="rememberFeatureEditorState" /> does this for you when the state
belongs to a screen: it saves the features, selection, draft and the active
`DrawTool`'s options. Android saved state fails above about 500 KB, so large
documents belong in a ViewModel.

## Validate edits

`validate` runs on each new feature and each feature whose geometry changed. A
message rejects the whole mutation: nothing changes, the mutation returns false
or null, and `validationError` holds the message until the next accepted
change. A drag that would break the rule sticks at the last valid position, and
a finish that would break it keeps the draft:

## Write a tool

<Api of="EditorTool" /> is the behavior extension point. A tool receives
<Api of="EditorEvent" />s and mutates the state through its public functions,
so undo works without extra code. Every event carries `project` and
`unproject` for the map that delivered it, and each press carries an
<Api of="EditStep" />; passing it as `undoStep` merges a whole drag into one
step. Delegating to an `inner` tool with `by` keeps every behavior you do not
override.

This wrapper snaps taps and drags to nearby vertices by rewriting the event's
pointer before the inner tool sees it:

<Code code={region(editing, "snapping")} lang="kotlin" title="SnappingTool.kt" />

`SelectTool` moves a selection in Web Mercator space, so a shape dragged toward
a pole grows on the ground. This wrapper moves it along a great circle instead
and leaves every other event to `SelectTool`:

<Code code={region(editing, "geodesic-move")} lang="kotlin" title="GeodesicMoveTool.kt" />

1. <Api of="FeatureEditorState.featureBefore" /> returns the feature as it was
   when the drag started, so each frame applies the whole offset from the press
   rather than accumulating rounding.
2. <Api of="mapPositions" /> transforms every position and keeps rings closed.

A toolbar that highlights the active tool compares instances the app holds:
`editor.tool === select`. `is SelectTool` is false for a wrapper.

## Draw your own feature layers

<Api of="FeatureEditorLayers" /> composes <Api of="EditorFeatureLayers" />,
<Api of="EditorDraftLayers" /> and <Api of="EditorHandleLayers" />. Call the
parts yourself to render features with your own layers, or to place the handles
above every base layer while the features stay under labels:

<Code code={region(editing, "app-layers")} lang="kotlin" title="App.kt" />

1. A synchronous source applies each drag frame without a delay.
2. Draft vertices are handles, so the two editor parts together draw the whole
   draft.

Everything the layers read is public: `features`, `selection`, `draft`,
`handles`, `activeHandle` and `hover`. Content in the map overlay, such as the
area label here, blocks editor input under it; a map layer does not.

<Aside type="tip">
  Two editors on one map need distinct `idPrefix` values and two `featureEditor`
  modifiers in the chain. The first in the chain claims a pointer first.
</Aside>
