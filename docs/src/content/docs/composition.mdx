<Api of="MapState" /> holds one map: its base style, its camera, and the
sources and layers that you declare. <Api of="MaplibreMap" /> draws a
`MapState` on the screen. The state is a separate object, so code outside the
map can use it. For example, a button elsewhere on the screen can move the
camera.

## The base style and your content

Every map starts from a base style. A base style is a style document, usually
published by a map provider at a URL. It contains sources, which supply the
data, and layers, which draw that data: roads, water, labels, and so on.

The trailing block of <Api of="rememberMapState" /> declares your own sources
and layers. The library adds them to the base style. It does not change the
layers of the base style.

<Code code={region(composition, "base-plus-content")} lang="kotlin" title="App.kt" />

Your layers draw above the layers of the base style, in the order that you
declare them: a later layer draws above an earlier one. To put a layer between
layers of the base style, for example under the labels, wrap it in an
<Api of="Anchor" />. [Add data to the map](/maplibre-compose/layers/) shows how.

The library adds a source to the map only while one of your layers uses it. A
source that no layer uses loads no data.

When `showStrongOnly` becomes true, the library adds the `strong-earthquakes`
layer. When it becomes false, the library removes that layer. When `dotColor`
changes, the library sets the new color on the existing `earthquakes` layer.

You do not call add or remove functions. Use `if`, loops, and parameters, as you
do with UI composables.

## Switching the base style keeps your content

When `baseStyle` changes, the map loads the new style document. The library
then adds your content to the new style, so your sources and layers stay on the
map. [Style the map](/maplibre-compose/styling/#switch-styles-at-runtime) shows
how to switch styles.

The content block composes again from the start for each style that the map
loads. Values that you `remember` inside the block reset at that point, so keep
app state that must outlast a style change outside the block. An `Anchor`
places your layers again among the layers of the new style.

## Change the map with handles

Some changes are commands, not declarations: hiding a layer of the base style,
setting the state of one feature, or reading the points inside a cluster. For
these, get a handle from `mapState.style`. <Api of="MapStyleState.layers" />
returns a <Api of="LayerHandle" /> for a layer ID.
<Api of="MapStyleState.sources" /> returns a <Api of="SourceHandle" /> for a
source ID or for a source object that you declared.

## Layer and source IDs

MapLibre identifies each layer by a text ID, and you choose the ID of each layer
that you declare. The ID must be different from every other layer on the map,
including the layers of the base style. See <Api of="Layer" /> for what happens
when an ID repeats. Keep each ID the same across recompositions: a different ID
is a different layer, so the library removes the old layer and adds a new one.

Other functions find layers by ID. An `Anchor` can name a layer of the base
style, <Api of="MapState.queryRenderedFeatures" /> can return features from
only some layers, and `mapState.style.layers` returns a handle by ID.

Sources that you remember get their ID from the library, so refer to them by
the source object. To draw data from a source of the base style, get it by its
ID with <Api of="getBaseSource" />.
