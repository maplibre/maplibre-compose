# Common API gaps

Capabilities the underlying MapLibre SDKs already provide that MapLibre Compose
has no cross-platform API for.

This is a staging document, in the same spirit as
[MAPLIBRE_NATIVE_FFI_FEEDBACK.md](./MAPLIBRE_NATIVE_FFI_FEEDBACK.md): a place to
write findings down while they are fresh, to be converted into issues and
roadmap entries rather than lived in. The difference is direction —
`MAPLIBRE_NATIVE_FFI_FEEDBACK.md` is what we want _from_ maplibre-native-ffi,
and this is what we could build _with_ what already exists.

Nothing here is a desktop bug. Every entry was found by diffing the public
surface of the FFI's `MapHandle`, `RuntimeHandle`, and `RenderSessionHandle`
against desktop call sites during the desktop FFI rewrite, and then asking
whether the other platforms could do it too. Adding any of them means designing
a common API first, so none belongs in that branch.

Availability is **verified** where the symbol was found in the shipped SDK and
_unverified_ where nobody has looked yet.

## Ready to design

Every native platform can already do these, so the common API is the only
missing piece.

### Style light

Position, color, intensity, and anchor of the style's light source, which fill
extrusions shade against.

- FFI: `setStyleLightJson`, `setStyleLightProperty`, `styleLightProperty`
- Android: `org.maplibre.android.style.light.Light` — **verified**
- iOS: `MLNLight` — **verified**
- Web: `Map.setLight` — _unverified_

Naturally a Compose API: a `Light` composable inside `MaplibreMap`'s content,
set the same way layers are.

### Offline database merge

Merging a side-loaded offline database into the running one, which is how an
application ships pre-downloaded regions rather than making every user download
them.

- FFI: `startMergeOfflineRegionsDatabase`,
  `takeMergeOfflineRegionsDatabaseResult`
- Android: `OfflineManager.mergeOfflineRegions` — **verified**
- iOS: _unverified_
- Web: not applicable

Would be one suspending function on the existing `OfflineManager` interface, so
this is the smallest entry here.

### Custom geometry source

A source whose tiles are generated by application code on demand, rather than
fetched or held in memory. The basis for on-the-fly grids, procedural geometry,
and very large client-side datasets.

- FFI: `addCustomGeometrySource`, `setCustomGeometrySourceTileData`,
  `invalidateCustomGeometrySourceTile`, `invalidateCustomGeometrySourceRegion`
- Android: `CustomGeometrySource`, `CustomGeometrySourceOptions` — **verified**
- iOS: `MLNComputedShapeSource` — _unverified_
- Web: no direct equivalent

The design work is the callback boundary: MapLibre calls back on its own worker
threads to ask for a tile, which has to become something safe to implement from
Kotlin.

### Location indicator layer

MapLibre's built-in user-location puck — a style layer with a position, bearing,
and accuracy radius, rendered by the map rather than composed over it.

- FFI: `addLocationIndicatorLayer`, `setLocationIndicatorLocation`,
  `setLocationIndicatorBearing`, `setLocationIndicatorAccuracyRadius`,
  `setLocationIndicatorImageName`
- Android: `org.maplibre.android.location.LocationIndicatorLayer` — **verified**
- iOS: _unverified_
- Web: no direct equivalent

Worth weighing against drawing the puck as ordinary layers from
`org.maplibre.compose.location`, which is portable and already how the demo does
it. The native indicator's advantage is that it interpolates and renders in the
same frame as the map.

## Blocked on another platform

The FFI can do these; at least one other platform cannot, so a common API would
have to be partial.

### Feature state writes

Per-feature state that expressions read with `feature-state`, used for hover and
selection styling without rebuilding source data.

- FFI: `setFeatureState`, `getFeatureState`, `removeFeatureState` on the render
  session
- Android: absent from the shipped SDK — **verified**
- iOS: absent from the shipped SDK — **verified**
- Web: MapLibre GL JS has `setFeatureState`

The expression side already exists in the common API
(`org.maplibre.compose.expressions.dsl.Feature.state`), so only the write side
is missing. Blocked until the mobile SDKs expose it, or until they move onto the
native core — see the roadmap's "Native core integration on Android and iOS".

### Projection mode

Switching between Mercator and globe projections.

- FFI: `projectionMode`
- Android: not found in SDK 13; `maps/Projection` is screen-to-coordinate
  conversion, which is a different thing — _needs a closer look_
- iOS: _unverified_
- Web: MapLibre GL JS supports globe

### Resource transform

A hook to rewrite every resource URL before it is requested — how applications
add API keys, route through a proxy, or redirect to a local mirror.

- FFI: `setResourceTransform`, `clearResourceTransform`
- Android: not found — _needs a closer look_
- iOS: _unverified_
- Web: `transformRequest` on the map options

Desktop already has a broader mechanism in `DesktopResourceProvider`, which
serves resources rather than just rewriting their URLs.

## Already tracked

### Map snapshots

The FFI can do this today with `requestStillImage` and `readPremultipliedRgba8`,
and Android (`MapSnapshotter`) and iOS (`MLNMapSnapshotter`) both ship
snapshotters — **verified**.

Already on the roadmap as
[#28](https://github.com/maplibre/maplibre-compose/issues/28), blocked on
decoupling the style API from the `MaplibreMap` composable. Recorded here only
so that a future audit does not rediscover it as new.
