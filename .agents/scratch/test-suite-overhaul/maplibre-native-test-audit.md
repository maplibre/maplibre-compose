# maplibreNativeTest class audit

Every test class under `lib/maplibre-compose/src/maplibreNativeTest/` as of
2026-08-31. Helpers (`BridgeMapFixture`, `FakeMlnFfiMapHost`,
`MlnFfiMapFixture`, `FfiTestPlatform`, `FfiComposeTestPlatform`,
`TestConcurrency`, `LiveMapAccess`, `ComposeRuntimeTestHost`) are not classes
under test.

Source set total: 38 test classes, 146 methods.

- Table A: 11 classes, 65 methods. No `BridgeMapFixture`, no GPU, no live
  MapLibre session.
- Table B: 27 classes, 81 methods. A map, a GPU, a cache database, or a Compose
  FFI host that talks to one of those.

`createCacheFile()` on Desktop and Android calls `FfiTestPlatform.initialize()`,
which loads the packaged native library. That is a process-wide library load,
not a MapLibre cache open. Table A still treats a class as cheap when it only
uses that helper for a temp path.

## FakeMlnFfiMapHost — what it can absorb

`FakeMlnFfiMapHost` records host calls (`acquire` / `complete` / `release` /
`draw` / `close`) and scripts acquire outcomes. It does not run MapLibre, does
not attach a render session, and does not hold a style or camera.

### Already absorbed

`MlnFfiMapSurfaceRecoveryTest` (16 methods). That is the whole current FakeHost
suite. Resize destination vs target, skip-last-target, recovery bounds, and
close-once already live there.

### Can absorb, with a small fake extension

These need a recording `MlnFfiMapHostSession` (`requestFrame`,
`withRendererAccess`) more than a richer `FakeMlnFfiMapHost`. Ticket 07 named
the idle/repaint _counts_.

| Class                   | What a fake can prove                                                                                                      | What must stay live                                                                                                                                                           |
| ----------------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MlnFfiMapIdleTest`     | Wrapper does not call `requestFrame` after a recorded settle (only if the session is fake and the scheduler is injectable) | mbgl itself going quiet after camera rest and after style reads. Those are native idle bugs. Keep all three live until that seam exists; then keep the camera-rest case live. |
| `MlnFfiMapRepaintTest`  | `MlnFfiStyleBinding` calls `requestFrame` after add/remove source/image and after `MAP_STYLE_LOADED`                       | That MapLibre actually drew. A count of `RENDERED` on a real session stays layer 3. Do not add pixels.                                                                        |
| `MlnFfiMapResizeTest`   | Host `resize` / acquire extent (already in SurfaceRecovery)                                                                | `attachCount` unchanged and `retargetCount` incremented — native session, ffi #485. Keep all three live.                                                                      |
| `MlnFfiSurfaceLossTest` | Host `onSurfaceLost` / `onSurfaceAvailable` order (already in SurfaceRecovery)                                             | Style identity, camera, attach count, feature-state replay into a real renderer. Keep all three live. The store half is already `MlnFfiFeatureStateStoreTest`.                |

### Cannot absorb

Native style, camera, projection, tiles, offline, or pixels. FakeHost is the
wrong seam.

- `CustomGeometrySourceTest`, `CustomVectorSourceNativeTest` — native tile
  callbacks and `isFullyLoaded`
- `GeoJsonSourceUpdateTest`, `GeoJsonSourceStyleReloadTest`,
  `VectorSourceQueryTest`, `UnknownSourceRestoreTest`, `TiledSourceAttachTest`,
  `ImageSourceAttachTest` — live source/style handles
- `MlnFfiStyleImageStretchTest`, `MlnFfiStyleImageScaleTest`,
  `MlnFfiLayerKeyRoundTripTest`, `UnsupportedLayerPropertyTest`,
  `LocationIndicatorLayerTest` — live `addImage` / `addLayer` / property
  readback
- `MlnFfiProjectionTest`, `MlnFfiTileLodTest`, `MlnFfiStyleFailureTest`,
  `MlnFfiGestureTokenOrderingTest` — live map / owner queue
- `MlnFfiMapPixelTest` — framebuffer (layer 5)
- `PlatformMapAccessTest` — live owner thread and `MapHandle`, no surface
- `MlnFfiOffline*`, `MlnFfiSharedCacheDatabaseTest` — runtime and cache, no host
- Table A except SurfaceRecovery — no host involved

### Ticket 07 restated

Move nothing else onto FakeHost until a recording host-session exists. When it
does, absorb only idle/repaint _request_ counts. Keep a live `BridgeMapFixture`
smoke for native attach, style survival, and camera (`MlnFfiSurfaceLossTest`
first two methods). Keep one live replacement smoke if the fake cannot represent
EGL/Metal teardown.

## Process-global seats (ticket 06)

Every `BridgeMapFixture.create` / `createMapFixture` opens a cache file and a
GPU driver in a process that already loaded one native library
(`FfiTestPlatform.initialize`: “one test process contains one native runtime”).

Classes that _are_ the shared-cache problem, not just neighbors:

1. `MlnFfiSharedCacheDatabaseTest` — two `RuntimeHandle`s, one file.
2. `MlnFfiOfflinePackTest`, `MlnFfiOfflineManagerTest`,
   `MlnFfiOfflineRuntimeTest` — open the cache schema without a map.
3. `PlatformMapAccessTest` — `RuntimeImplementation` + cache, no GPU.
4. `ImageSourceAttachTest` — process-global `Maplibre.setLogCallback`.
5. `UnsupportedLayerPropertyTest` — process-global Kermit writer, never removed.

`FileUrlTest` only loads the library via `createCacheFile()`. Stop doing that
and it drops off this list.
